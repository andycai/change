# CQRS 性能验证与迁移 功能需求文档

> 日期: 2026-06-18 | 状态: 草稿
> 父功能: CQRS 模块重构 - [README.md](./README.md)

## 概述

验证 CQRS 重构达成 0GC 性能目标，提供运行时监控能力，并完成现有代码迁移示例和指南。

## 用户故事

| 角色 | 场景 | 目标 |
|------|------|------|
| 框架维护者 | 验证重构后的性能 | 通过 Profiler 和单元测试确认 0GC 分配 |
| 运维开发者 | 生产环境性能监控 | 运行时埋点，超过阈值告警 |
| 业务开发者 | 迁移现有代码（如 Quest 模块） | 参考迁移示例和指南，完成改写 |

## 功能边界

**范围内：**
- **性能验证：**
  - 编写 0GC 分配单元测试（Class 模式 + Struct 模式）
  - 使用 Unity Profiler 验证热路径（`Send`/`Ask`/`Publish`）
  - 性能基准测试：对比重构前后的执行时间和 GC 分配

- **运行时监控：**
  - 埋点收集执行次数、耗时、GC 分配
  - 阈值告警（如单次执行 GC 超过 100 字节）
  - 监控数据暴露接口（可选：集成到现有监控系统）

- **代码迁移：**
  - Quest 模块迁移示例（`QuestCommandHandlers.cs` → 新模式）
  - 迁移指南文档：
    - Class Handler 迁移步骤（添加 `IPoolable`、实现 `Reset()`）
    - Struct 自处理迁移步骤（移除 Handler 类，Struct 实现 `Execute()`）
    - 异步 Command 迁移（改用 `IAsyncCommandHandler`）
    - Event 订阅迁移（Class Handler 保持不变 or 改用静态委托）

- **文档：**
  - API 使用文档（双模式选择指南）
  - 性能最佳实践
  - 常见问题（FAQ）

**范围外：**
- 全量代码迁移（仅提供示例和指南，业务代码自行迁移）
- 自动化迁移工具（手动改写）
- 性能优化超出 0GC 目标的部分

## 验收条件

- [ ] Class 模式 0GC 单元测试通过
- [ ] Struct 模式 0GC 单元测试通过
- [ ] Profiler 验证热路径 0GC 分配
- [ ] 性能基准测试完成，对比数据记录
- [ ] 运行时监控埋点就位，阈值告警可用
- [ ] Quest 模块迁移示例完成，代码可运行
- [ ] 迁移指南文档完成，覆盖所有场景
- [ ] API 使用文档和 FAQ 完成

## Decisions

| # | 决策点 | 选择 | 理由 | 影响范围 |
|---|--------|------|------|----------|
| 1 | 性能目标 | 严格 0 字节 GC 分配 | 继承自访谈决策 | 所有测试和验证 |
| 2 | 验证方式 | 单元测试 + Profiler + 运行时监控 | 三重保障，覆盖开发和生产环境 | 测试和监控实现 |
| 3 | 迁移策略 | 完全不兼容，手动改写 | 继承自访谈决策 | 业务代码迁移工作量 |
| 4 | 迁移优先级 | 示例优先（Quest），全量由业务团队自行安排 | 框架提供指南，不阻塞业务节奏 | 迁移计划 |

## 未决问题

| # | 问题 | 建议解决阶段 |
|---|------|-------------|
| 1 | 运行时监控数据的存储和查询方式（内存？日志？外部系统？） | design |
| 2 | 是否需要提供"兼容模式"桥接层，允许旧代码在过渡期运行？ | explore（评估成本和价值） |
| 3 | 性能基准测试的场景选择（典型 UI 操作？高频战斗逻辑？） | design |

## 约束与假设

- 假设：Quest 模块是典型的 UI 业务逻辑，迁移示例有代表性
- 假设：业务团队有足够时间窗口完成全量迁移
- 约束：不引入自动化迁移工具（成本高，收益有限）
- 约束：性能验证在 Unity Editor 和真机都需要通过
