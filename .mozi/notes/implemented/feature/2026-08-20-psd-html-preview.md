# Agent Note: 使用 PSD 合成画布生成独立 HTML 预览

Status: implemented

该决策已被[按图层生成可交互 HTML 页面](2026-08-20-interactive-psd-html-page.md)完全取代。整图 Base64 预览不再是受支持行为；保留本记录用于解释该方案为何曾被采用以及为何被撤销。

## 问题

PSD 导出流程只生成 Unity 使用的 JSON 和可选图层切图，策划或开发人员无法在不打开 Photoshop 的情况下快速核对导出对象是否对应完整页面。仅凭切图和图层坐标也无法可靠还原文本、蒙版、混合模式与图层效果。

## 决策

该决策实施时，`PsdParser` 曾从 `ag-psd` 提供的文档合成画布提取 PNG，并通过 `LayerTree.previewImage` 传递给 `HtmlPreviewGenerator`。CLI 在 JSON 同目录生成同基础名的 `.html` 文件。

该 HTML 曾将合成 PNG 作为 Base64 数据内嵌，并以 PSD 原始画布宽高作为图片固有尺寸；页面只做等比例响应式缩放，不重新解释或拼装图层。

该实现曾在写入 JSON 前生成 HTML 内容，并在 PSD 不包含可用合成画布时以 `PSD composite preview is unavailable` 失败。这些行为已随整图模式一起移除。

## 曾考虑的替代方案

**用图层切图和绝对定位 DOM 重建页面：** 该方案可以检查各图层边界，但当前模型没有完整文本内容、变换、蒙版和所有混合效果，重建结果会与 Photoshop 画面产生不可预测的偏差，因此不作为完整排版预览。

**生成独立预览 PNG 并由 HTML 引用：** 该方案能减小 HTML 文件，但移动或分享 HTML 时容易丢失旁边的图片依赖。内嵌图片增加文件体积，但更符合预览文件可直接打开和传递的用途。

## 验证

单元测试覆盖 PSD 合成画布提取、原始画布尺寸、Base64 图片内嵌、标题转义、缺失合成画布错误和 UTF-8 文件写入。TypeScript 构建与完整 Jest 测试用于验证 CLI 接线和既有导出行为没有回退。

## 后果

收益是 HTML 可以忠实展示 PSD 的最终合成页面，并且不依赖切图路径或浏览器字体环境。代价是解析期间会额外保留一份 PNG `Buffer`，Base64 编码还会使 HTML 比原始 PNG 大约增加三分之一；大型 PSD 的导出峰值内存和预览文件大小会相应增加。

后续验证表明，该收益不足以满足“按钮和控件必须可操作”的核心用途，因此该实现已从生产代码、数据模型和测试中完全移除。
