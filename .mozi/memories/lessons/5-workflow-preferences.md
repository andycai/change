# 5. Workflow & Preferences (工作流与个性化偏好)

*个人研发习惯和工具偏好*

- **生成示例默认不提交：** 将真实导出的 FairyGUI 示例工程列入提交计划后，用户明确要求不要提交 -> 生成产物只用于本地验收，除非用户明确授权，否则不暂存、不提交
- **构建与验证必须串行：** 将 `npm run build` 与测试/`node dist/...` 放进并行工具调用，验证可能消费旧产物或与构建竞争 -> 任何构建后验证命令必须在 build 成功后单独串行执行
- **子项目命令与路径：** 多次在错误 workdir 执行子项目命令，或在子项目目录的补丁、搜索和测试参数中重复带 `PSDExporterProject/` 前缀，导致命令失败或验证旧代码 -> `apply_patch` 固定在仓库根单独执行；搜索、构建和测试固定在子项目 workdir 使用无前缀相对路径，并与补丁串行执行
- **子项目外部路径：** 在 `PSDExporterProject/` 工作目录用仓库相对路径检查输入或生成产物，导致路径检查提前失败 -> 子项目命令中的仓库外输入和输出统一使用绝对路径，或先在仓库根完成路径检查
- **子项目依赖脚本：** 在仓库根用 Node 脚本校验子项目生成 XML，Node 无法解析 `PSDExporterProject/node_modules` 中的依赖 -> 依赖子项目包的诊断脚本固定在 `PSDExporterProject/` 工作目录运行
- **源码修改入口：** 先用临时文件再 `cp` 覆盖源码，绕过了仓库要求的补丁入口 -> 源码修改始终直接使用 `apply_patch`
- **简单文件编辑：** 用 Python 脚本改了少量源码/测试文本 -> 简单手工编辑必须优先使用 `apply_patch`
- **编写代码前：** 直接执行编写代码 -> 需要询问是否创建新的 worktree 并在新的 worktree 中执行 
- **代码提交风格：** 提交时没使用前缀 -> 始终使用 `feat:`、`fix:`、`chore:`、`docs:`、`refactor:` 等前缀
